# Numbers Guard — честность чисел

Проект опровергает мифы; одна ошибка в числе обесценивает всё. Этот скилл — ворота перед коммитом.

## Процедура

1. **Собери числа.** Найди все числа и количественные утверждения в изменённых файлах (`story/05_draft/*`, `src/i18n/*`, компоненты, `docs/*`).
2. **Сверь с моделью.** Для каждого числа найди функцию в `src/model/tick.ts` и тест в `src/model/tick.test.ts`, который его закрепляет. Нет теста → напиши тест; число не выводится из модели → добавь параметр в `data/params.json` с `source`, `source_url`, `verified`.
3. **Сверь с источником.** Параметр с `verified: false` можно показывать игроку только с пометкой-сноской «оценка проекта». Источник со статусом ⚠ в `research/sources.md` — открой ссылку, проверь; если подтвердился — поменяй статус на ✅ и дату; если нет — сообщи автору через `research/open-questions.md`.
4. **Запусти тесты.** `npm test` должен быть зелёным.
5. **Проверь согласованность.** Одно и то же число одинаково во всех местах: сценарий, i18n, docs, график концепта. Округления — как в сценарии (например, «≈12 ч» для 11,8 ч).
6. **Отчёт.** Таблица: число · где встречается · функция/параметр · тест · источник · статус (ок / исправлено / вопрос автору).

## Запрещено

- Выдумывать ссылки, номера arXiv, DOI, цитаты.
- Менять числа «для драматургии». Драматургия — в образах, не в цифрах.
- Смешивать параметры будущего Оракула и сегодняшних чипов.
- Удалять тест, чтобы он не падал.

## Обновление данных по новым статьям

Новая статья меняет параметр → сначала `research/open-questions.md` с цитатой-пересказом и ссылкой, решение принимает автор; после решения — `params.json` + тесты + тексты в одном коммите, в сообщении коммита — ссылка на источник.
